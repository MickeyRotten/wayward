# Wayward feedback list

## INSTRUCTIONS
This is the running log of change requests and new features for the project. How to work it:

- **Pick up tasks from the top down**, but use judgement — group related items when it's more efficient.
- When you finish a task, **flip its checkbox** (`[ ]` → `[x]`) and write a short **Done** note directly under it: what actually changed, which files, and any follow-ups or deliberate omissions. Include the **commit ID**.
- **Commit and push** each finished task (or a coherent batch) to the working branch.
- If a task turns out to be infeasible, ambiguous, or a bad idea, **say so under the task** instead of silently skipping it — note why and what you'd do instead.
- **Keep the format**: one task per entry, `[ ]`/`[x]` checkbox, separated by `---`. **Newest tasks go at the bottom.**
- Related tasks are grouped under `###` sub-headings for readability; keep new items near their theme when it's obvious, otherwise append at the end.

> The full history of completed work lives in `TODO_old.md`.

---
[x] Fix models (notably the **DeepSeek** family, which is preferred for narration) that write out a reply, delete it, and immediately write a follow-up that continues the deleted text.
  Done: two distinct root causes, both fixed. (1) **Preamble discard in the agentic loop** (the primary cause) — DeepSeek narrates the whole beat and THEN appends a state-write tool call in the same message; the loop treated that prose as throwaway "preamble", discarded it from the player's view, KEPT it in the transcript, and forced a re-narration — so the next round *continued* text the player could no longer see. Now: when the streamed content is a substantial narration and every requested tool is a non-prose-shaping safe write (`set_scene`/`grant`/`remove`/`consume`/`equip`/`unequip`), the loop keeps the beat and stops — no re-narration (`_SAFE_WRITE_TOOLS`, `narrator_agent.py`); and when content genuinely IS preamble and is discarded, it's dropped from the transcript too (`content=None`) so the model re-narrates cleanly instead of continuing deleted text. `skill_check`/read tools still force a clean redo (their result must be free to shape the prose). (2) **Inline `<think>…</think>` leak** — some DeepSeek deployments (custom/NIM providers, or providers without a reasoning parser) emit chain-of-thought inline in `delta.content` instead of a dedicated reasoning field, so it rendered as narration and then the real answer followed. Added a streaming-aware `_ThinkStripper` (`openrouter.py`) that routes a LEADING think block to the reasoning channel in both stream parsers, tolerant of a tag split across deltas; only a leading block is stripped, so ordinary prose containing the token is untouched. Commits: f92da11, f4e83f0. Tests: `test_think_stripping.py`, `test_narrator_preamble.py`.

### Performance & state ownership (from the Wayward / Loom / Aimon comparison)
---
[x] Cut the per-turn cost and take the state the narrator shouldn't own. See `docs/wayward-vs-loom-vs-aimon.md` for the analysis this came from.
  Done, as one coherent change:

  **Per-turn model calls: 2–8 → 1–2.**
  - `NarratorConfig.action_suggestions_mode` now defaults to **`inline`** — the options ride the narrator's trailing block instead of buying a second generation every turn. `separate` stays as the reroll/self-heal path (which is what it's good at).
  - **`set_scene` left the native tool schema.** It cost a whole round-trip (call → execute → tool result → call again to narrate) to write four strings the model could append to the beat it had just written. Scene now rides the new trailing **`<<<TURN>>>`** block (`server/ai/turn_block.py`) with the options — one marker to teach, one thing to parse, one thing to strip. The handler survives for the legacy text protocol only.
  - `max_tool_rounds` default **6 → 4** (the most common round is gone), and a **duplicate safe write inside one turn** is now suppressed rather than applied twice.
  - **Chronicler cadence** — `OpenRouterSettings.worldbuilding_interval` (1-10, default **2**, Config → Agents & Tools). It runs every N turns over the whole span since it last ran (`chronicler_span`, deterministic in the turn number, no bookkeeping). Halves a whole extra generation *and* reads better: judging "is this genuinely new?" from a single beat is exactly what made it re-propose the entry it wrote two turns ago. This is the front half of the open "make lore updates additive / only when there's something new" item.
  - `_HISTORY_WINDOW` **500 → 160** (~80 turns, comfortably past the largest prompt budget; 500 was ten times what any context can hold and every turn paid for the read).

  **The prompt is five tiers now** (`build_prompt`), oldest-and-general → newest-and-specific. Two rules: *every fact is stated once*, and *anything the history can contradict is stated AFTER the history*. The roster, the pack and the task list used to sit hundreds of tokens BEFORE the beats that contradict them, and the later text is the one the model believes — which is why companions who left kept getting voiced. New **PARTY roll call** (`server/ai/roster.py`) is re-read every turn and emitted **even when the party is empty** ("the player is ALONE"), because the empty case is where the history drifts most. Also a **performance** win: tier 1 is byte-identical between turns, so it stays a cacheable prompt prefix — the old order invalidated it every turn. One `CONTEXT_TURNS` window now feeds lore matching and the spotlight, so "mentioned" means one thing.

  **The clock is the server's** (`server/ai/clock.py`). `day` left the protocol entirely — it was a narrator-written integer nothing validated, free to freeze, jump or run backwards. The narrator emits a `duration` off a fixed ladder; an unknown label falls to the smallest step (garbage is unrepresentable, not clamped), a block with NO duration still advances time (an unparseable turn can't freeze the world), and `night` anchors to the next 07:00 so sleeping lands on a morning. Time reaches the player and the model as a **phase word** only. `ChatMessage.scene_minutes` (additive migration) makes reversal free; swipe/regenerate advance from where the *turn* started, so re-telling never ages the world twice. `simplify_location` keeps the narrowest segment of a stapled compound ("Boars Head Tavern - Damp Cellar" → "Damp Cellar") — which also stops the backdrop art changing when the model changes its mind about the prefix.

  **The dice are seeded** (`server/ai/dice.py`). `random.randint` behind a regenerate button is an open save-scum hole. Rolls are pure in `(turn, variant, actor, skill, difficulty)`: a regenerate re-*tells*, a swipe re-rolls. Both classic seeding traps are regression-tested — a raw FNV hash fed to `% sides` leaks its parity, and per-die suffixed seeds mean **2d6 can never roll 7**.

  **No-op writes.** An op that sets X to what X already is is not an op: a `grant_item` with no explicit count for something already stowed, an `equip` of what's already worn, an `unequip` of an empty slot, a `remove_item` for something not held. The last two are now no-ops rather than *failures* — reporting a failure invites the model to try again.

  **Android hardware Back** closes the open overlay instead of quitting the app (`client/src/lib/useBackHandler.ts`, wired into the mobile Inspector and the nav's More sheet).

  Tests: `server/tests/test_clock_dice_block.py` (25), `server/tests/test_turn_block_e2e.py` (3, through the real route with a stubbed provider), new tier-order cases in `test_prompt_builder.py`, `client/src/lib/clock.test.ts`. Server 170 passing, client 24.

  **Deliberately not done here** (next slice, in rough value order): collapsing the two narration protocols onto one lenient path with native tools as a read-only accelerator; a `reconcileBlock`-style fold of proposed state against current state (needs the writes to move out of the generation loop first); one narrator feature-flag map replacing the four scattered switches; splitting the 1800-line `SettingsPanel`; a first-run setup screen; Places; the append-only journal.
